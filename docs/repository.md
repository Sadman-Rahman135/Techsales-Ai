# Repository structure (blueprint §14)

Where everything lives, and how it maps to the illustrative layout in [IMPLEMENTATION_PLAN.md §14](IMPLEMENTATION_PLAN.md#14-repository-structure).
`backend/tests/unit/test_repository.py` checks that every path in the tables below exists, so this page can't
silently go stale: move a folder, update the row.

## 1. Layout

| Path | What it holds |
| --- | --- |
| `README.md` | Purpose, features, setup, scripts, testing, deployment, what is not built |
| `compose.yaml` | Local data services; profile `llm` the local models; profile `app` the whole system from its images |
| `compose.gpu.yaml` | Runs the local models on an NVIDIA GPU (`-f compose.yaml -f compose.gpu.yaml`) |
| `LLM/models.json` | The local models: repository, pinned revision, size and SHA-256 of each file (ADR-026) |
| `LLM/README.md` | Which models, why, how to download and run them (the files go in `LLM/models/`, git-ignored) |
| `.env.example` | Every setting with its default; copy to `.env` (git-ignored) |
| `.github/workflows/ci.yml` | CI: lint, types, unit + integration tests, golden gates, contract checks, secret and dependency scans |
| `docs/IMPLEMENTATION_PLAN.md` | Source of truth: requirements, design, tests, release |
| `docs/architecture.md` | Containers, data flows, ADR-001…027, the §19 decisions |
| `docs/api-contract.md` | The HTTP API for people: auth, routes, errors, streaming, sample requests |
| `docs/contracts/openapi.json` | The HTTP API for machines (generated, checked in CI) |
| `docs/contracts/voice-knowledge-api.md` | The frozen voice contract `knowledge-answer.v1` for Project 2 |
| `docs/threat-model.md` | Assets, actors, STRIDE threats with the test that proves each control |
| `docs/data-model.md` | Tables, delete behaviour, RLS, Chroma metadata, version lifecycle |
| `docs/evaluation.md` | Acceptance gates G1–G10 and how they are measured |
| `docs/operations.md` | Runbook: health, backup, rebuild, retention, alerts, incidents, load test |
| `docs/deployment.md` | Deploying to a host: what to provision, secrets, release, rollback, smoke test |
| `docs/risk-register.md` | §17 risks with their mitigations, tests and what's still open |
| `docs/definition-of-done.md` | §18 audit: every item with its evidence or why it's open |
| `docs/product-vision.md` | Personas, permission matrix, user stories |
| `docs/scope.md` | MVP cut line, P0/P1/P2 by milestone, non-goal guardrails |
| `docs/dependency-versions.md` | Pinned versions and why |
| `docs/demos/` | Evidence per plan section: test lists, manual runs, screenshots |
| `design-system/MASTER.md` | UI tokens, components, accessibility checklist (+ `pages/`, `content-guide.md`) |
| `backend/Dockerfile` | One image for api, worker and migrations |
| `backend/pyproject.toml` | Direct dependency pins and tool settings |
| `backend/constraints.txt` | Full lock (generated by `scripts/lock_backend.py`) |
| `backend/migrations/` | Alembic migrations (reviewed by hand: RLS, CHECKs, triggers) |
| `backend/app/main.py` | FastAPI app: routers, middleware, lifespan |
| `backend/app/config.py` | Settings and their validation (refuses unsafe deployed configs) |
| `backend/app/api/` | HTTP routes, auth dependencies, errors, rate limits, telemetry |
| `backend/app/core/` | Permissions, tokens, signed links, privacy, log hygiene, time, request metrics |
| `backend/app/db/` | SQLAlchemy models and tenant sessions |
| `backend/app/ingestion/` | Validation, scanning, parsing, chunking, embeddings, worker, reconcile, rebuild |
| `backend/app/integrations/chroma.py` | The only way to query Chroma: the Principal-filtered index (ADR-004) |
| `backend/app/rag/` | The LangGraph workflow: intent, retrieval, evidence, prompts, model adapters, citations |
| `backend/app/services/` | Documents, versions, storage, analytics, metrics, alerts, retention, orders, tickets, reviews, exports |
| `backend/app/evaluation/` | Golden runner, gates, access probes, lifecycle suite, G2 audit, load test |
| `backend/app/demo/` | Fictional demo and golden corpora |
| `backend/app/cli/` | Seed users, contract checks, the post-deploy smoke test, S3 bucket setup |
| `backend/tests/unit/` | Fast tests, no services |
| `backend/tests/integration/` | Tests against Postgres and Chroma (compose stack), incl. the golden gates |
| `frontend/Dockerfile` | Standalone Next.js image |
| `frontend/app/` | Routes: `chat`, `assistant`, `admin`, `login`, `support`, `status`, BFF `api` handlers |
| `frontend/components/` | Chat, admin and quality components |
| `frontend/lib/` | BFF client, auth and session, chat and document helpers (+ `*.test.ts`) |
| `evaluation/gates.yaml` | Gate thresholds (the only place to change them) |
| `evaluation/golden_questions/` | golden-v1 and golden-v2 (each frozen by its sha256; v2 = v1 with label corrections, ADR-028) |
| `evaluation/exploration/` | Development queries; tune here, never on golden-v1 |
| `evaluation/datasets/` | The M3 hand-picked set |
| `evaluation/baselines/` | Accepted gate values for regression checks |
| `evaluation/reports/` | Run reports (only those quoted as evidence are kept) |
| `evaluation/audits/` | G2 grounding audit sheets |
| `infra/docker/postgres/init/` | Creates the RLS-restricted app and worker roles and the test database |
| `infra/deploy/rehearsal/` | The deployment rehearsal: compose file, Caddyfile, TLS-only `pg_hba.conf` |
| `infra/deploy/postgres/roles.sql` | The same roles for a managed database |
| `infra/deploy/s3/` | Bucket policy and lifecycle rules |
| `scripts/` | Demo documents, backups, the dependency lock, the deployment rehearsal, GitHub issue setup |
| `scripts/download_models.py` | Downloads the local models from their pinned revisions and verifies every file |

## 2. Plan §14 → this repository

| Plan §14 | Here | Why it differs |
| --- | --- | --- |
| `docs/api-contract.md`, `threat-model.md`, `evaluation.md` | `docs/api-contract.md`, `docs/threat-model.md`, `docs/evaluation.md` | Same |
| `app/api/{auth,documents,chat,analytics,internal}.py` | `backend/app/api/` | Plus `health`, `metrics`, `deps`, `errors`, `ratelimit`, `telemetry`, `security`, `orders`, `tickets`, `reviews`, `exports` |
| `app/core/{auth,permissions,errors,logging}.py` | `backend/app/core/` + `backend/app/api/errors.py` | HTTP errors live with the API; logging is `core/log_hygiene.py` |
| `app/schemas/` | Next to their routes and in `backend/app/rag/schemas.py` | Response models sit with the code that returns them |
| `app/services/{storage,documents,orders,tickets}.py` | `backend/app/services/` | `orders` and `tickets` (ADR-029), `reviews` and `exports` (ADR-030) |
| `app/ingestion/{parsers,cleaning,chunking,embeddings,jobs}.py` | `backend/app/ingestion/` | `parsing.py`, `normalize.py`, `worker.py` |
| `app/rag/{state,graph,nodes,retriever,prompts,citations}.py` | `backend/app/rag/` | State and nodes are in `graph.py`; retrieval through `integrations/chroma.py` |
| `tests/{unit,integration,evaluation}/` | `backend/tests/unit/`, `backend/tests/integration/` | The evaluation gate runs as an integration test (`test_golden_gate.py`) |
| `frontend/app/{chat,admin,documents,login}/` | `frontend/app/` | Documents are under `admin/documents`; plus `assistant`, `support` |
| `frontend/lib/{api,auth,types}/` | `frontend/lib/` | Flat files; types sit with their helpers |
| `evaluation/{golden_questions,scoring,reports}/` | `evaluation/` + `backend/app/evaluation/` | Scoring is code (`gates.py`, `runner.py`) |
| `sample-data/{public-manuals,fictional-policies,seed}/` | `backend/app/demo/` + `scripts/make_demo_docs.py` | Fictional documents are generated from code, so nothing binary is committed; seed users via `python -m app.cli.seed` |
| `infra/{docker,deploy,monitoring}/` | `infra/docker/`, `infra/deploy/`, `backend/Dockerfile`, `frontend/Dockerfile`, `compose.yaml` | Each Dockerfile sits with its code; `infra/deploy/` holds the rehearsal, DB roles and S3 policies; monitoring is built in (ADR-021) |
